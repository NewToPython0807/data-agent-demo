# V3 Agent 效果评测方案

> **说明**：本文件是 v1 方案（单轮判定）；v2 方案见 [AGENT_EVAL_PLAN-v2.md](./AGENT_EVAL_PLAN-v2.md)，采用「首轮 + 按假设继续」双协议，覆盖 80 条用例。

- **版本**：v1.0（2026-11-02）
- **对象**：轻量「智能问数」Data Agent V3（语义层增强 / 查询计划 / 拒答 / 澄清 / 自动纠错 / golden / 评测）
- **数据**：信用卡维度模型（14 张表，固定随机种子造数）
- **方式**：黑盒 HTTP 调用（模拟真实前端），对照"参考 SQL 的执行结果"判定

## 一、评测目标

1. 量化 Agent 的**问答准确率**（生成的 SQL 执行结果是否与参考结果一致）；
2. 量化**拒答 / 澄清 / 安全拦截**行为是否正确（不多拒、不漏拒）；
3. 量化**响应延迟**（ask / execute / 端到端）；
4. 找出失败类型（SQL 错误、口径错误、过度拒答、该澄清未澄清等），给出优化建议。

## 二、测评集设计（66 条）

| 类别 | 数量 | 说明 | 期望行为 |
| --- | --- | --- | --- |
| 正常问数 normal | 25 | 单指标、分组、Top N、时间/渠道/商户筛选、快照期末值 | 生成可执行 SQL 且结果与参考一致 |
| 边界确认 boundary | 10 | 时间/口径/范围不明确 | 返回 clarify（澄清） |
| 拒答 refusal | 9 | 库中没有的数据、超范围、敏感信息 | 返回 refused，不生成 SQL |
| 多轮追问 multi_turn | 5 | 基于上一轮 SQL 的追问 | 结果与参考一致 |
| 语义层 semantic | 5 | 同义词/业务术语（交易金额、不良率、发分、用分、循环信用） | 结果与参考一致 |
| 安全拦截 guard | 4 | 删除/清空/更新/DDL | 拒答或被只读保护拦截（400） |
| 空结果 empty | 3 | 合法但无数据 | 正常执行、0 行、有异常提示 |
| 复杂查询 complex | 5 | 窗口/HAVING/排名/占比 | 结果与参考一致 |

## 三、指标定义

| 指标 | 定义 |
| --- | --- |
| **准确率 accuracy** | `正常 + 空结果` 中结果与参考一致的条数 / 总数 |
| **SQL 可执行率** | 生成 SQL 能成功执行的条数 / 需执行的总数 |
| **拒答召回率** | 应拒答且拒答的条数 / 应拒答总数 |
| **过度拒答率** | 本应正常回答却被拒答的条数 / 正常类总数 |
| **澄清命中率** | 应澄清且澄清的条数 / 应澄清总数 |
| **安全拦截率** | 写操作被拒答或 400 拦截的条数 / 写操作总数 |
| **整体通过率** | 所有类别按各自期望行为判定的通过条数 / 总条数 |
| **延迟** | ask（模型生成）、execute（执行）、total 的均值 / P50 / P90 / P95 |
| **计划完整率** | 返回计划且含 tables/metrics/joins 等字段的条数 / 总条数 |

> 结果比对：单值按容差（默认 0.01）比较；多行结果按"行集合"比较（数值按容差，文本精确）。参考 SQL 无法执行时标记为 `reference_error`，不计入准确率但单独报告。

## 四、运行方式

前置：本地或云端服务已启动、`.env` 配置了 `DEEPSEEK_API_KEY`、已执行信用卡造数。

```powershell
cd "C:\Users\Administrator\Desktop\data agent"
.venv\Scripts\python run_eval.py --base-url http://127.0.0.1:8000 --username admin --password test123
```

可选参数：
- `--repeat N`：每条问题重复 N 次（评估稳定性，默认 1）；
- `--limit N`：只跑前 N 条（调试用）；
- `--category normal`：只跑某一类；
- `--output eval_results.json`。

运行后生成：
- `eval_results.json` / `eval_results.csv`：逐条明细；
- `docs/AGENT_EVAL_REPORT.md`：评估报告（含总体/分类指标、失败案例、优化建议）。

## 五、判定口径

- **正常**：`/api/ask` 返回 SQL → `/api/execute` 成功 → 结果与参考一致；
- **空结果**：执行成功且 `row_count=0`；
- **拒答**：`/api/ask` 返回 `refused=true`；
- **澄清**：`/api/ask` 返回 `clarify=true`；
- **安全**：`refused=true` 或 `/api/execute` 返回 400（只读保护）。

## 六、报告结构

1. 评测概述与环境；
2. 数据集构成；
3. 指标定义；
4. 总体结果（准确率/拒答/澄清/安全/延迟）；
5. 分类结果；
6. 失败案例分析（按类别列前 N 条）；
7. 优化建议（由失败类型自动生成 + 人工补充）。
