## 2. 项目背景与目标

在 V1（单账号、上传 CSV/Excel、SQLite、云端问数）**已上线**的基础上，做第二版：

- **查得更准**：增加「指标/语义层」，让 AI 懂业务口径与中文名称。
- **查得更深**：在 10 万行以内数据上支持多表关联、聚合后筛选、窗口函数等复杂查询。
- **界面更专业**：改为「左导航 / 中对话流 / 右结果区」三段式布局。
- **结果可带走**：查询结果支持导出 CSV。

数据规模：**10 万行以内**；使用者：公司内部小团队（5–50 人），本版仍为**单账号**。

---

## 3. 用户与使用场景

- **使用者**：公司内部小团队（5–50 人），本版仍共用一个登录账号（不做多用户/RBAC）。
- **使用场景**：
  1. 上传业务数据（CSV/Excel），维护表/字段中文名与指标口径。
  2. 用中文提复杂问题（多表关联、分组后筛选、排名/窗口等）。
  3. 审核生成的 SQL、确认执行，在三段式界面查看结果。
  4. 把查询结果导出为 CSV。

---

## 4. 第二版范围

### 4.1 必须完成

1. **指标/语义层定义模块**：表/字段中文名 + 指标定义，**网页表单手工维护**。
2. **复杂查询能力**：10 万行以内，支持**多表关联、聚合后筛选（HAVING）、窗口函数**。
3. **前端三段式改版**：左导航 / 中对话流 / 右结果区。
4. **结果导出 CSV**。
5. **测试造数**：测试阶段按需提供（具体要求届时再确认）。

### 4.2 暂不做

1. 行级/列级权限、大模型可切换、多用户 RBAC。
2. VPN/专线落地、CI/CD、监控告警、备份。
3. 接入公司现有数据库（本版仍以上传 CSV/Excel 为主）。
4. 报表/看板/订阅、AI 自动洞察。
5. 语义层的「同义词」与「表间关联关系定义」。
6. 图表可视化。
7. 指标定义的 Excel/JSON 批量导入。
8. 多租户 SaaS。

### 4.3 后续建议（未确认，不进入本版）

- 指标 Excel/JSON 批量导入。
- 表间关联关系定义（提升多表 JOIN 准确率）。
- 图表可视化。
- 行级/列级权限、多用户、SSO。
- 大模型可切换 / 私有化部署。

## 5. 功能需求

### FR-1 表/字段中文名维护

- **做什么**：在网页上为已上传的表、字段填写中文名与业务含义，保存后供问数使用。
- **验收标准**：填写并保存后，语义层页面显示正确；问数时提示词中包含对应中文名。

### FR-2 指标定义（网页表单手工维护）

- **做什么**：用网页表单定义指标，包含：指标名称、计算口径（如 `SUM(销售额)`）、说明、关联表/字段、**单位**、**适用维度**（如地区/时间）；修改指标时**保留变更历史版本**（可追溯口径变化）。
- **验收标准**：定义「销售额 = SUM(销售额)，单位=元，维度=地区/时间」后，提问「销售额是多少」能生成正确 SQL 并返回结果；修改口径后，可在历史中查看旧版本。

### FR-3 语义层注入问数

- **做什么**：生成 SQL 时，把表结构、字段中文名、指标口径一起交给大模型。
- **验收标准**：使用中文名/指标名提问，生成的 SQL 能正确对应到表与字段。

### FR-4 多表关联查询

- **做什么**：支持涉及多张表的 JOIN 查询。
- **验收标准**：上传两张可关联的表，问「关联后统计…」能生成 JOIN SQL 并返回正确结果。
- **说明**：本版未定义表间关联关系，JOIN 键由大模型根据表/字段名推断；代码结构**预留「表关系定义」扩展点**，后续可加。

### FR-5 聚合后筛选（HAVING）

- **做什么**：支持 GROUP BY 后按聚合结果筛选。
- **验收标准**：问「统计每个地区销售额大于 X 的…」能生成 `GROUP BY … HAVING …` 并返回正确结果。

### FR-6 窗口函数

- **做什么**：支持 `ROW_NUMBER`、`RANK`、`SUM OVER` 等窗口函数。
- **验收标准**：问「每个地区销售额排名前 3」等，能生成窗口函数 SQL 并返回正确结果。

### FR-7 前端三段式改版

- **做什么**：改为「左导航 / 中对话流 / 右结果区」布局；左导航默认四项：**数据表 / 指标 / 历史 / 设置（含退出登录）**；中栏保留提问、SQL 审核/修改、执行；右栏展示结果。
- **验收标准**：三栏布局可用；导航切换、提问→审核→执行→结果的主流程正常。

### FR-8 结果导出 CSV

- **做什么**：**只针对当前查询结果**支持一键导出 CSV。
- **验收标准**：导出的 CSV 与页面当前结果一致，可用 Excel 正常打开；历史记录不支持导出（本版）。

### FR-9 测试造数

- **做什么**：测试阶段生成模拟数据，**大致范围：3–5 张表，每表 1–10 万行**（用于覆盖多表关联、HAVING、窗口函数等复杂查询）。
- **验收标准**：细节（字段类型、中文/空值/边界、关联键等）在测试阶段再确认。

---

## 6. 核心交互流程

1. **维护语义层**：上传数据 → 为表/字段填中文名 → 定义常用指标 → 保存。
2. **复杂问数**：中文提问 → 系统结合表结构 + 中文名 + 指标口径生成 SQL → 用户审核（可改）→ 确认执行 → 右栏查看结果。
3. **导出**：结果区点「导出 CSV」→ 下载文件。

---

## 7. 非功能需求（仅已确认内容）

- **数据规模**：10 万行以内。
- **轻量化**：沿用 SQLite 单文件、少依赖、Docker 部署。
- **单账号**：沿用 V1 登录方式（本版不做多用户/RBAC）。
- **部署**：沿用现有腾讯云服务器。
- 性能/并发硬指标、HTTPS/域名：未确认，列入第 9 节。

## 8. 数据与权限（仅已确认内容）

- **数据来源**：网页上传 CSV/Excel。
- **存储**：SQLite（沿用）。
- **语义层数据**：新增表/字段中文名、指标定义（新增数据表，不修改 V1 已有数据）。
- **权限**：单账号，沿用 V1。

## 9. 决策记录与待确认事项

### 9.1 第 9 节待确认项确认结果

| 编号 | 事项 | 确认结果 |
| --- | --- | --- |
| Q1 | 多表 JOIN 关联键 | 本版靠 AI 推断，代码预留「表关系定义」扩展点 |
| Q2 | 10 万行查询性能 | 不设硬指标，跑通优先，超时再优化 |
| Q3 | 指标口径维护 | 本人维护，保留变更历史版本 |
| Q4 | 指标字段 | 基础（名称/口径/说明/关联表字段）+ 单位 + 适用维度 |
| Q5 | 导出 CSV 范围 | 只导出当前查询结果 |
| Q6 | 左导航项 | 数据表 / 指标 / 历史 / 设置（含退出登录） |
| Q7 | 测试造数 | 大致 3–5 张表、每表 1–10 万行，细节测试阶段确认 |

### 9.2 剩余风险（不影响开工）

- 多表 JOIN 准确率依赖 AI 推断，复杂关联可能不准（后续可加表关系定义）。
- 10 万行窗口函数/多表关联的实际耗时需实测。
- 指标口径由单人维护，需与实际业务口径保持一致。
